# BOON.SS Pro

BOON.SS Pro is a Gemini powered AI chat app with streaming replies, MongoDB backed accounts and synced conversation history.

The first screen keeps the BOON.SS welcome layout. Choose **Try demo** to open the full chat page. Guests can send seven messages before BOON asks them to create an account or sign in. The guest counter is stored in that browser; signing in or creating an account resets it.

## Features

- Streaming AI responses, with stop and regenerate controls
- English and Hinglish replies, with Markdown formatting for headings, lists, links and code
- MongoDB email and password accounts, signed sessions and per-user cloud chat history
- Local conversation history, search and saved prompts
- Image and text file attachments
- Browser voice input and read-aloud, plus copy and share actions
- Portfolio contact form with email notification and automatic acknowledgement
- Rotating Earth hero and LinkedIn/GitHub profile links
- Edit a prompt and regenerate its answer, or remove a message
- Responsive desktop and mobile chat layout
- BOON.SS welcome page with a full-screen chat demo and seven-message guest allowance

## Requirements

- Node.js 20 or newer
- A Gemini API key
- MongoDB local instance or MongoDB Atlas database
- A Resend account and verified sender domain for contact form email

## Local setup

1. Install dependencies: `npm install`
2. Copy `.env.example` to `.env` and fill in the values below.
3. Start the frontend and API server: `npm run dev`
4. Open the Vite URL printed in the terminal (usually `http://localhost:5173`).

The development command runs Vite and the Node API together. The Vite server proxies `/api` calls to `http://localhost:8787`.

## Environment variables

| Variable | Purpose |
| --- | --- |
| `GEMINI_API_KEY` | Server-side Gemini API key |
| `GEMINI_MODEL` | Optional model override; defaults to `gemini-3.1-flash-lite` |
| `MONGODB_URI` | MongoDB connection URI |
| `MONGODB_DB` | Database name; defaults to `boon` |
| `SESSION_SECRET` | Long random secret for signing login sessions |
| `VITE_FORMSPREE_ENDPOINT` | Public Formspree endpoint for the portfolio contact form |
| `PORT` | API server port; defaults to `8787` |

Keep backend credentials in the host's secret settings or local `.env`; never expose them through `VITE_` variables or commit `.env`. The Formspree endpoint is public configuration, not a secret.

## MongoDB and accounts

Create a MongoDB database user and allow the development machine or hosted backend in Atlas Network Access. On first use, BOON creates a unique index for user emails and an index for each user's recent chats. Sign-up and sign-in use email and password; passwords are salted and hashed on the server. Chat records are scoped to the signed-in account. Signed-in users can update their display name, archive and restore chats, move chats to Trash, and permanently delete chats from Trash. Demo chat archives are stored only in that browser's local storage; account-only profile and Trash actions are not available in demo mode.

## Contact form (Formspree)

The contact form submits directly to Formspree. Create a form in Formspree, set its notification recipient and any autoresponder there, then copy its endpoint (`https://formspree.io/f/your_form_id`) into `VITE_FORMSPREE_ENDPOINT` in local `.env` or the deployment environment. The browser only needs this public form endpoint; no Formspree private API token is used in the frontend. The form includes a `_gotcha` honeypot field.

To test locally, add a line such as `VITE_FORMSPREE_ENDPOINT=https://formspree.io/f/your_form_id` to `.env`, then restart the dev server. In Formspree, configure the destination email (`sonalsuryvanshi@95gmail.com`) and enable an autoresponder if you want visitors to receive an automatic thank-you email.

## Deploy to Render

This project includes a Render Blueprint in `render.yaml`. The Node server serves the Vite `dist/` build and the `/api/*` endpoints from the same web service.

1. Push the project to a GitHub repository.
2. In Render, choose **New → Blueprint**, connect the repository, and select `render.yaml`.
3. Set `VITE_FORMSPREE_ENDPOINT` to your public Formspree form endpoint in Render's environment settings. Also configure `GEMINI_API_KEY` and `MONGODB_URI` for the AI and account features. `SESSION_SECRET` is generated by the Blueprint.
4. Deploy. Render runs `npm install && npm run build`, then `npm start`; `/api/health` is the health check.
5. Test the live contact form and verify that the notification arrives at `sonalsuryvanshi@95gmail.com` and the acknowledgement reaches the submitted address.

For account sync, allow the Render service to connect to MongoDB Atlas (configure Network Access appropriately). Render's free web service may sleep when idle, so the first request after inactivity can take longer. Use a paid instance if always-on response is required.

## Other production deployment

For other hosts, set `VITE_FORMSPREE_ENDPOINT` in the build environment before running `npm run build`, then run `npm start`. The MongoDB URI must be reachable from the backend host.

- `npm run preview` — preview the production frontend build
